01 ACM — AWS Certificate Manager Security

ACM provisions, manages, and auto-renews TLS/SSL certificates. It abstracts key management entirely for managed certs — you cannot export private keys from them.

Cert placement rules
CloudFront Cert must be in us-east-1 regardless of origin region
ALB Same region as the load balancer
API Gateway Same region as the API (regional endpoint)
EC2 direct Not supported — must import cert instead
Key behaviors
Renewal Automatic for managed certs, 60 days before expiry
Private key Never exportable for ACM-managed certs
Import Allowed — you manage renewal for imported certs
Integrations CloudFront, ALB, NLB, API GW, Elastic Beanstalk
⚡ Exam Trap

CloudFront cert in us-east-1 is the #1 ACM trap. Even if your origin is in ap-southeast-1, the cert for CloudFront must be provisioned in us-east-1.

When to choose CloudHSM

Regulatory requirement for Level 3, BYOK where AWS must not see key material, Oracle TDE, SSL offloading on EC2, custom crypto via PKCS#11, or compliance requiring dedicated hardware.

KMS Cross-Region — Critical Rules

KMS keys do NOT replicate automatically across regions. For cross-region scenarios (S3 replication with SSE-KMS, encrypted AMI copy, RDS snapshot copy), you must create a separate CMK in each destination region and explicitly specify it.

Multi-Region Keys (MRK) are the exception — they share the same underlying key material and have a key ID prefixed with mrk-. MRKs enable decryption in the destination region without re-encryption, critical for active-active architectures and disaster recovery.

⚡ Exam Trap

"I copied an encrypted AMI to another region — why can't I launch it?" → Because the source KMS key doesn't exist in the destination region. You need a CMK in the destination and must specify it during the copy.

WAF Rule hierarchy

Web ACL → Rule Groups (managed or custom) → Rules (IP set, geo match, rate-based, regex, SQL injection, XSS, managed rule group). Priority order matters — lower number = evaluated first.

⚡ Exam Trap

WAF does NOT attach to NLB or EC2 directly. NLB is Layer 4 only — if you need L7 inspection in front of NLB, you must put a CloudFront distribution or ALB in front of it.

Key insight

EFA is a superset of ENA — it includes all standard ENA functionality. On Windows, EFA behaves exactly like ENA. The OS-bypass benefit only activates on Linux with libfabric-aware applications (MPI, ML collective ops).

Reserved

Guaranteed pool for a specific function. Also acts as a hard cap — function cannot exceed this, protecting other functions in the account.

Pre-initialized execution environments. Eliminates cold starts entirely. Costs money even at zero invocations. Use for latency-sensitive functions.

Unreserved

Shared account-level pool. Default for functions with no reserved concurrency. One function can consume the entire pool.

08 EC2 — Dedicated Hosts & Host Affinity Compute
Dedicated Instance

Runs on hardware not shared with other AWS accounts. AWS may move the instance to a different physical host after stop/start. You have no visibility into host-level details (sockets, cores). Per-instance billing.

Dedicated Host

You control a specific physical server. Visibility into socket count, core count, host ID. Can target a specific host for instance launches. Per-host billing. Supports multiple instance sizes from the same family (e.g., all m5 variants).

Host Affinity
HOST

Instance always restarts on the same physical host after stop/start. Critical for per-socket/per-core BYOL licenses (SQL Server, Oracle, Windows Server).

DEFAULT

AWS picks the host after stop/start. The instance may move, which can break license compliance if the license is tied to a specific host ID.

BYOL use case

Dedicated Host + Host Affinity=HOST is the required combination for BYOL software (Oracle DB, SQL Server Enterprise, Windows Server with SA) that licenses per physical socket or core. You can provide auditors the specific host ID as proof of isolation.

10 Global Accelerator + ALB Network
How Global Accelerator works

Global Accelerator provides two static Anycast IP addresses that are globally advertised. User traffic enters the AWS network at the closest AWS edge location, then travels the low-latency AWS backbone to reach your endpoint — instead of traversing the unpredictable public internet.

Endpoints can be ALBs, NLBs, EC2 instances, or Elastic IPs in any region. Failover happens in ~30 seconds based on health checks. Traffic dials let you shift 0–100% of traffic per endpoint group, enabling canary and blue/green deployments.

⚡ Exam Trap

Any question mentioning fixed IPs for a global application, gaming/UDP, or multi-region TCP failover → Global Accelerator, not CloudFront. CloudFront is the answer when the question mentions caching, static assets, or HTTP/S only.

Scale-out hook uses

Bootstrap: pull config from S3/SSM Parameter Store, join domain, warm application caches, register with service mesh, install agents, run compliance checks. Complete with CONTINUE when ready.

Scale-in hook uses

Graceful drain: flush in-flight requests, push final logs to S3/CloudWatch, deregister from service discovery, take EBS snapshot, run decommission scripts. Complete with CONTINUE to allow termination.
